# 엣지 LLM 기반 IoT 이상 감지 시스템 — 프로젝트 정리 (한국어)

> MIRU 2026 (제29회 화상인식·이해 심포지엄, 나가사키) Track B 포스터 발표 프로젝트.
> YoungWook Park · Siah Kim · Zepa Yang — 순천향대학교 컴퓨터공학과 · Efficient Computing Lab

## 한 줄 요약

Raspberry Pi 5가 수집한 4종 센서 데이터를 Jetson Orin Nano 위의 GRPO 파인튜닝 LLM(Qwen2.5-3B, 4bit 양자화)이 실시간 해석해 3단계 안전 상태(steady/monitoring/emergency)를 판정하는, 클라우드 없는 엣지 완결형 모니터링 파이프라인.

## 문제 정의

기존 IoT 모니터링은 채널별 임계값 규칙에 의존한다. 이 방식은 센서 간 교차 상호작용(전류·온도 동시 상승은 각각의 상승과 다른 위험 신호)을 포착하지 못하고, 새 이상 유형마다 규칙을 다시 짜야 한다. 이 프로젝트는 LLM의 자연어 추론으로 다중 센서를 통합 판단하되, 8GB 엣지 디바이스 안에서 완결되도록 만들었다.

단순 on-off 제어기가 목적이 아니다 — 정화(cleansing)/배기(evacuation) 개입이 다른 모달리티에 미치는 효과까지 판단에 반영하는 **시스템 항상성(homeostasis) 유지의 파일럿**이 이 시스템의 지향점이다.

## 시스템 구성 (4단계)

1. **센서 수집** — Raspberry Pi 5: DHT22(온습도), MPU-6050(진동 RMS), MQ-135(VOC), ACS712-30A(전류) → 5필드 JSON
2. **추론 게이트웨이** — Jetson 위 FastAPI가 센서 JSON을 자연어 프롬프트로 변환
3. **LLM 추론** — Qwen2.5-3B-Instruct를 MLC-LLM(Apache TVM)으로 q4f16_1 컴파일(1.617GB), 호출당 1.2–1.8초
4. **규칙 기반 안전 백스탑** — 4개 하드 임계값(온도>80°C, 전류>25A, 진동>2.5g, VOC>500ppm)을 LLM 출력과 무관하게 강제, SQLite에 기록

## 핵심 결과 (평가 코호트 명시)

- **정확도**: 배포 모델 V13이 held-out 벤치마크(학습 미사용)에서 LLM 단독 63% (21/33). V8(31%)부터 데이터 증강 커리큘럼으로 순차 개선.
- **시스템 레벨**: 규칙 백스탑 결합(추론의 ~8% 교정) 시 동일 벤치마크 100%.
- **양자화 비용**: 동일 체크포인트·동일 벤치마크 통제 비교(V14)로 fp16 39% → q4f16_1 33% = **−6%p**, 대신 3.8× 압축(6.2→1.617GB)으로 8GB 메모리 제약 충족.
- **지연**: 실측 100회 기준 end-to-end 중앙값 2.3초 (SLA 5초).

## 실패에서 얻은 것 — V14 mode collapse

monitoring 클래스 과잉 예측을 고치려고 해당 오답에만 페널티를 −1.0→−1.5로 키웠더니(비대칭 reward shaping), 모델이 페널티가 낮은 한 클래스로 도피 — 실패 22건 중 21건이 단일 클래스로 수렴하며 33%로 붕괴했다. GRPO는 그룹 상대 어드밴티지 기반이라 최저 페널티 클래스로의 수렴이 PPO보다 가속된다.

**교훈: GRPO 보상 크기는 오류 유형 간 대칭으로 유지하고, 클래스 불균형은 보상이 아니라 데이터 리샘플링으로 잡는다.** 실패한 V14는 양자화 손실의 통제 비교쌍으로 재활용했다.

## 배운 점

- 실패도 데이터다 — 실패 실험이 논문의 정량 근거(양자화 손실 측정)가 됐다.
- 성능 수치는 반드시 평가 코호트(train/test/deploy)와 함께 보고해야 비교 가능성 논란을 피할 수 있다.
- LLM 단독 정확도의 한계는 시스템 설계(규칙 백스탑)로 보완했다 — 모델 성능과 시스템 안전성은 별개 레이어다.

## 향후 계획

프롬프트에 슬라이딩 윈도우 센서 이력 추가(시계열 문맥), 7B급 양자화 베이스 평가, 개입 효과 피드백 루프(항상성 유지 완성).
